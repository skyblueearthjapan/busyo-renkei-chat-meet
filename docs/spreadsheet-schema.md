## 1. README

説明用シート。運用ルールや凡例を記載。

### 内容

- タイトル: 部署クイック連絡アプリ：ベーススプレッドシート（マスタ＆ログ）
- 目的: Chat/MeetスペースID/URLは後から追記OK、Meet終了後にSession_Memosで要点記録
- 基本運用:
  1. Dept_Masterで部署を登録（ChatスペースID/URLは後から追記OK）
  2. UIからChat/Meet実行 → Interaction_Log へ自動記録
  3. Meet終了後、Session_Memosへ1分メモを入力（テンプレ選択＋短文）
- シート構成の説明
- 入力ルール:
  - 青文字: 人が入力・変更する想定
  - 黒文字: 自動生成・参照値
- メモ: Chat/Meetの"会話内容の全文"は保存せず、要点（用件/決定事項/...）のみ記録

## 7. History_View

履歴ビューシート（将来用）。

### 説明

- タイトル: 履歴ビュー（アプリ表示用の集約例）
- 目的: UI側で参照しやすい形に整形するための"ビュー"用
- 運用: 必要に応じてGASで生成/更新
- 例: 最新50件のメモを表示
- 方針: QUERY関数やGASで自動転記する想定。動的配列関数は使わない。

## ID採番ルール

### event_id

- 形式: E0001, E0002, ...（Eプレフィックス + 4桁ゼロ埋め）
- 管理: PropertiesService（スクリプトプロパティ）に `nextEventId` を保持
- 競合防止: LockService を使用

### memo_id

- 形式: M0001, M0002, ...（Mプレフィックス + 4桁ゼロ埋め）
- 管理: PropertiesService（スクリプトプロパティ）に `nextMemoId` を保持
- 競合防止: LockService を使用

### rule_id

- 形式: R001, R002, ...（Rプレフィックス + 3桁ゼロ埋め）
- 手動管理（マスタデータのため）

## 関連図

```
Dept_Master (dept_id)
    │
    ├──→ Connection_Rules (発信部署/宛先部署)
    │
    ├──→ Interaction_Log (発信部署/宛先部署)
    │         │
    │         └──→ Session_Memos (関連 event_id)
    │
    └──→ Session_Memos (発信部署/宛先部署)

Lookup (カテゴリ/値)
    │
    ├──→ Interaction_Log (チャネル/優先度/ステータス)
    │
    └──→ Session_Memos (問い合わせ種別/結果/優先度/ステータス)
```

## 注意事項

1. **ChatスペースID/URLは後から追記OK**: 初期登録時は空でも動作する
2. **会話全文は保存しない**: 要点メモのみ記録（プライバシー/運用負荷考慮）
3. **有効フラグ**: `Y` のみUIに表示
4. **表示順**: 数値が小さいほど上位表示
